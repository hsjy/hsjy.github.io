本文记录一次基于 `Docker + ROS1 Noetic + Intel RealSense D405 + Piper 机械臂 + AprilTag + easy_handeye` 的手眼标定完整流程。

手眼标定的核心目的，是求解相机坐标系与机械臂坐标系之间的空间变换关系，使相机观测到的三维信息能够正确映射到机械臂坐标系下，从而为后续视觉抓取、点云定位、机械臂操作等任务提供基础。

## 手眼标定基本概念

手眼标定主要分为两种形式：

- **眼在手外（Eye-to-Hand）**
- **眼在手上（Eye-in-Hand）**

### 眼在手外

相机固定不动，标定板安装在机械臂末端并随机械臂运动。  
此时需要求解的是：

```text
相机坐标系 -> 机械臂基座坐标系
```

### 眼在手上

相机安装在机械臂末端，标定板固定在桌面上。  
此时需要求解的是：

```text
相机坐标系 -> 末端坐标系 -> 机械臂基座坐标系
```

![handeye_form](assets/img/posts/26-2/HandEye/form.jpg)
_图1：眼在手上（左） 眼在手外（右）_

本次流程采用的是 **眼在手上** 的方式。

### Docker 环境配置

#### Docker 配置文件

如果 Docker 拉取镜像失败，或者希望自定义 Docker 镜像存放位置，可以修改 `/etc/docker/daemon.json`。

```bash
sudo mkdir -p /etc/docker

sudo tee /etc/docker/daemon.json <<EOF
{
  "data-root": "/mnt/data/users/hs/data/docker",
  "registry-mirrors": [
    "https://docker.mirrors.ustc.edu.cn",
    "https://docker.xuanyuan.me",
    "https://registry.docker-cn.com",
    "https://docker.1ms.run"
  ]
}
EOF

sudo systemctl daemon-reload
sudo systemctl restart docker
```

其中：

- `data-root` 用于指定 Docker 镜像和容器数据的存储路径；
- `registry-mirrors` 用于配置镜像加速源。

配置完成后，可以拉取 `hello-world` 测试：

```bash
docker run hello-world
```

#### 添加 Docker 用户组

为了避免每次使用 Docker 都需要 `sudo`，可以将当前用户加入 `docker` 用户组。

```bash
whoami
echo $USER

grep docker /etc/group

sudo groupadd docker
sudo usermod -aG docker $USER
```

添加后需要退出当前终端并重新登录，或者重启 SSH 会话。

验证当前用户是否加入 Docker 组：

```bash
id $USER
```

输出中应包含 `docker`。

再次测试：

```bash
docker ps
```

如果没有权限错误，说明配置成功。

#### Docker Socket 权限问题

如果出现类似错误：

```text
permission denied while trying to connect to the Docker daemon socket
```

可以检查 `/var/run/docker.sock` 权限：

```bash
ll /var/run/docker.sock
```

必要时临时添加权限：

```bash
sudo chmod o+rw /var/run/docker.sock
```

> 这种方式适合本地实验环境。正式生产环境中应谨慎修改 Docker Socket 权限。

### ROS Noetic
#### 拉取Noetic镜像

本次使用 ROS1 Noetic 桌面完整版本：

```bash
docker pull osrf/ros:noetic-desktop-full
```

查看镜像：

```bash
docker images
```

#### 启动 ROS Docker 容器

启动容器：

```bash
docker run -it \
  --name ros_handeye \
  --network=host \
  --privileged \
  --env="DISPLAY" \
  --env="QT_X11_NO_MITSHM=1" \
  --volume="/tmp/.X11-unix:/tmp/.X11-unix:rw" \
  --volume="$HOME/.Xauthority:/root/.Xauthority:rw" \
  --volume="/mnt/data/users/hs/data/ros_handeye:/root/hs" \
  -v /dev:/dev \
  osrf/ros:noetic-desktop-full \
  /bin/bash
```

参数说明：

| 参数                                           | 作用                              |
| ---------------------------------------------- | --------------------------------- |
| `--name ros_handeye`                           | 指定容器名称                      |
| `--network=host`                               | 使用宿主机网络，方便 ROS 节点通信 |
| `--privileged`                                 | 允许容器访问 USB、相机等设备      |
| `--env="DISPLAY"`                              | 转发图形界面                      |
| `--env="QT_X11_NO_MITSHM=1"`                   | 避免部分 Qt 程序显示异常          |
| `/tmp/.X11-unix`                               | 挂载 X11 Socket                   |
| `$HOME/.Xauthority`                            | 允许容器访问宿主机图形界面        |
| `/mnt/data/users/hs/data/ros_handeye:/root/hs` | 挂载工作目录                      |
| `-v /dev:/dev`                                 | 允许容器访问宿主机设备            |

```bash

```

```bash
roscd apriltag_ros/launch
```

> 一个终端的 Shell 会话中，通常只应明确激活当前需要的 ROS 工作空间。多个工作空间的 `setup.bash` 叠加可能会影响 `ROS_PACKAGE_PATH`、`CMAKE_PREFIX_PATH` 等环境变量。
> {: .prompt-info }

编辑 `continuous_detection.launch`：

```xml
<launch>
  <arg name="launch_prefix" default="" />
  <arg name="camera_name" default="/camera/color" />
  <arg name="image_topic" default="image_raw" />
  <arg name="queue_size" default="1" />

  <node pkg="apriltag_ros"
        type="apriltag_ros_continuous_node"
        name="apriltag_ros_continuous_node"
        clear_params="true"
        output="screen"
        launch-prefix="$(arg launch_prefix)">
    <remap from="image_rect" to="$(arg camera_name)/$(arg image_topic)" />
    <remap from="camera_info" to="$(arg camera_name)/camera_info" />
    <param name="publish_tag_detections_image" type="bool" value="true" />
    <param name="queue_size" type="int" value="$(arg queue_size)" />
    <rosparam command="load" file="$(find apriltag_ros)/config/settings.yaml"/>
    <rosparam command="load" file="$(find apriltag_ros)/config/tags.yaml"/>
  </node>
</launch>
```

### 修改 move_group 参数

进入 `easy_handeye` 的 launch 文件，修改 `calibrate.launch` 中的 `move_group` 默认值。

将默认值从：

```xml
<arg name="move_group" default="base" />
```

改为：

```xml
<arg name="move_group" default="piper" doc="the name of move_group for the automatic robot motion with MoveIt!" />
```

该名称需要与 Piper 的 MoveIt 配置中的 planning group 保持一致。

### 启动标定

```bash
roslaunch easy_handeye calibrate.launch \
  eye_on_hand:=true \
  robot_base_frame:=arm_base \
  robot_effector_frame:=link6 \
  tracking_base_frame:=camera_color_optical_frame \
  tracking_marker_frame:=tag_1 \
  freehand_robot_movement:=true
```

参数说明：

| 参数                      | 参数值                       | 说明                   |
| ------------------------- | ---------------------------- | ---------------------- |
| `eye_on_hand`             | `true`                       | 相机安装在机械臂末端   |
| `robot_base_frame`        | `arm_base`                   | 机械臂基座坐标系       |
| `robot_effector_frame`    | `link6`                      | 机械臂末端坐标系       |
| `tracking_base_frame`     | `camera_color_optical_frame` | 相机光学坐标系         |
| `tracking_marker_frame`   | `tag_1`                      | AprilTag 坐标系        |
| `freehand_robot_movement` | `true`                       | 允许手动移动机械臂采样 |

## 开始采样

启动后，可以在 RViz 中添加实时检测图像：

```text
Add -> By topic -> /tag_detections_image -> Image
```

随后不断改变机械臂姿态进行采样。本文实验中共采样约 18 组。

采样建议：

- 姿态变化应尽量丰富；
- 不要只在一个小范围内移动；
- 保证 AprilTag 始终能被相机稳定识别；
- 避免过近、过远或图像严重模糊；
- 采样时尽量覆盖不同角度和不同位置。

## 发布手眼标定 TF

根据标定得到的变换结果，创建 launch 文件：

```bash
nano ~/hs/piper_ros/src/piper/launch/publish_handeye_tf.launch
```

写入：

```xml
<launch>
  <arg name="parent_frame" default="link6" />
  <arg name="child_frame" default="camera_link" />

  <arg name="x" default="-0.017849522259870684" />
  <arg name="y" default="0.04264774756745868" />
  <arg name="z" default="-0.01741992783852021" />

  <arg name="qx" default="0.06424826100400814" />
  <arg name="qy" default="-0.07033404397853582" />
  <arg name="qz" default="-0.0446295849349991" />
  <arg name="qw" default="0.9944513479120615" />

  <node pkg="tf"
        type="static_transform_publisher"
        name="camera_handeye_tf_publisher"
        args="$(arg x) $(arg y) $(arg z) $(arg qx) $(arg qy) $(arg qz) $(arg qw) $(arg parent_frame) $(arg child_frame) 100" />
</launch>
```

启动：

```bash
roslaunch piper publish_handeye_tf.launch
```

> `easy_handeye.yaml` 中使用的是 `camera_color_optical_frame`，但上方 launch 文件发布的是 `link6 -> camera_link`。这是因为 RealSense ROS 会自动发布 `camera_link -> camera_color_optical_frame` 的静态变换，因此整体 TF 链仍然可以连通。
> {: .prompt-info }

```text
/camera/depth/color/points
```

添加方式：

```text
Add -> By topic -> /camera/depth/color/points -> PointCloud2
```

![rviz_pointcloud_placeholder](assets/img/posts/26-2/HandEye/rviz_pointcloud.png)
_图6：RViz 中显示机械臂、TF 与点云_

需要注意：

- 点云是真实世界中物体在相机视野下的投影；
- 点云不会“贴”在机械臂末端；
- 如果相机朝下拍摄，点云应出现在机械臂下方；
- 如果相机朝右拍摄，点云应出现在机械臂右侧；
- 控制机械臂运动时，点云应随相机一起移动。

## 常见问题

### Docker 无权限访问相机

检查是否使用了：

```bash
--privileged
-v /dev:/dev
```

同时确认相机在宿主机上可见：

```bash
lsusb
```

### ROS 工作空间找不到包

通常是没有正确加载对应工作空间：

```bash
source /opt/ros/noetic/setup.bash
source ~/hs/xxx_ws/devel/setup.bash
```

如果多个工作空间互相覆盖，建议重新打开终端并只加载当前需要的工作空间。

### AprilTag 无法识别

检查：

- Tag ID 是否与 `tags.yaml` 一致；
- Tag 尺寸是否正确；
- 图像话题是否是 `/camera/color/image_raw`；
- `camera_info` 是否正常发布；
- 光照是否充足；
- 标定板是否过小、过远或模糊。

### easy_handeye 无法采样

检查：

- `robot_base_frame` 是否存在；
- `robot_effector_frame` 是否存在；
- `tracking_base_frame` 是否存在；
- `tracking_marker_frame` 是否存在；
- TF 树是否连通；
- MoveIt 是否正常启动。

### RViz 中点云位置不对

检查：

```bash
rosrun tf tf_echo link6 camera_color_optical_frame
```

并确认：

- `publish_handeye_tf.launch` 中的四元数顺序正确；
- `parent_frame` 和 `child_frame` 没有写反；
- RealSense 的 `camera_link -> camera_color_optical_frame` 是否存在；
- 点云话题是否来自正确相机。

## 标定总结

这次手眼标定从最初的不熟悉，到逐步完成 Docker、ROS1、RealSense、AprilTag、Piper 机械臂、easy_handeye 和 RViz 验证，过程非常曲折。

从 ROS2 切换到 ROS1，是因为当前生态中 ROS1 的教程、工具和兼容性更加成熟；从不熟悉 Docker，到能够配置镜像源、挂载设备、运行图形界面；从安装相机 SDK 到理解 ROS 中的话题、TF 树和坐标变换，整个过程基本都是在不断试错中梳理出来的。

虽然最终标定结果不一定完全精确，但完整跑通这一流程本身就是一个重要起点。对于后续视觉抓取、点云定位和机械臂控制来说，这套流程可以作为进一步优化和迭代的基础。
